## 本次执行第一阶段

1. 本地以 web 为静态服务根目录运行原站，记录首页和现有示例的筛选、图表选择、CSV 导出路径；记录一个 CSV 上传到模板的现有行为。
2. 新增工作台入口及“打开数据／试用示例”空状态。完成导入预览、分析画布、字段配置和数据明细。在现有静态结构中按职责维护 JS、CSS。02 是已打开示例的布局参考，其中的示例值在正式产品中必须来自当前文件。
3. 先打通普通 CSV。复用文本读取逻辑，让解析结果有独立列标识、原始表头、类型和行数据。普通表直接保留所有列；旧示例沿用原有模板匹配。重复列名显示区分，空表头生成可辨名称，行宽异常给出源行提示。
4. 从真实字段填充分组和数值选项，首轮支持条形图、求和与平均、一个分类筛选。编号保留前导零。类型不适于计算时提供可用字段；区分零与缺失值。用同一批筛选记录更新图、摘要与明细。只含文本的表可先看明细，并提供按组计数。
5. 保留内置示例、旧模板上传、主题、导出及原来可用的操作入口。工作台新增控件均可键盘操作，弹窗取消后焦点返回触发处。文件名、表头和单元格按照普通文本呈现。

## 第二阶段排期 · 第一阶段评审后执行

1. 将解析与业务模板映射解耦，给普通表接入 XLSX、XLS、TSV、TXT 和 JSON。统一文件选择提示、支持清单、预览与错误处理。Excel 读取独立于文本解码，解析依赖固定版本并记录来源及许可；解析库随项目本地提供。
2. 工作簿多表先选择再导入，预览显示当前表名、行列数和字段类型。对日期、前导零文本、空值、没有缓存的公式及合并表头给出可见结果。延续 8 MiB 文件限制，先测典型表，按结果设单元格上限，记录浏览器与样本规模。
3. 文本补齐跨行引号、转义双引号、制表符、UTF-8 BOM 和 GBK。JSON 验证 01 中列出的三类形状，混合结构、坏 JSON、空工作表等场景提供可读错误。工作簿解析中允许取消；切换工作表或文件后旧结果不可覆盖新结果。
4. 测试至少各用一份真实格式的 XLSX、XLS、TSV、分隔 TXT、JSON，核对预览及最终汇总；包含双工作表选第二张、GBK 中文、跨行备注、JSON 第二行新增列、空工作表、超过限额、损坏文件、取消后原图可用。保存可分享的脱敏样例及期望值。
