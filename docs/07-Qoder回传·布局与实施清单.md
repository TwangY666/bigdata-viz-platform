## 3. 与 06 方案的两处冲突（需你拍板，我不擅自改）

1. **报告默认含明细名单。** 现在 `buildReport()` 无条件写入「数据明细（前 200 行）」；方案第四步要求"确认默认报告中没有报名名单"、导出原始明细由用户主动选择。建议：默认关闭 + 显式勾选，勾选状态在报告里注明。
2. **报告不写筛选条件与时间范围。** 报告元信息只有来源、行数、生成时间；方案要求"标明时间、筛选条件、指标口径及数据量"。建议第一批就补，否则第二批试玩必然返工。

另有一处小问题沿用上次记录：保存页面设置后 `applySiteText()` 会把 `document.title` 改回站点名，覆盖工作台的「表名 · 分析工作台」。不影响功能，等你定优先级。

## 6. 实施顺序（第一批）

1. **N6 记录级 CSV 解析** — 先修正确性地基，两条路径共用一个 splitter；夹具 C 回归，确认既有 177 项断言不退。
2. **N1 任务配置 + N2 角色映射** — 门店任务落地；默认建议借 `matchHeaders` 打分；缺列时说明影响而非隐藏。
3. **N5 首页任务卡** — 只放"比较门店销售"一张可用，其余按方案标注待接入，避免看起来已完成。
4. **N3 分组下钻** — `charts.js` 加 `data-key` 与可聚焦标记，工作台做事件委托；明细态 + 键盘 + Esc。
5. **N4 时间范围三态** — 缺日期 / 单月 / 跨月；摘要与报告共用同一份期间文案。
6. **N7 报告两处修正** — 补筛选条件与时间范围与口径；默认去掉明细名单，导出明细改为显式勾选。
7. **N8 工作台同源导出** + 全套验收与截图回传。

风险与判断：

- 主要新增量在 **N3 下钻**（要动 `charts.js`，影响全部图元）和 **N6 解析**（两条路径行为必须一致，否则第 5 节夹具 B 通不过）。
- 净额用**同列带符号求和**即可，第一批不需要把 `Calc` 接进普通表。若你的真实表是"收入列 + 退款列"分开的，就必须先抽 `Calc` 的公共状态——这是范围决策点，请你按手上的表形态定一下。
- `Clean` / `Calc` 目前都绑 dash 状态，普通表要复用需先解耦；第一批不做，第三批活动场景会用到，届时单列一轮。
